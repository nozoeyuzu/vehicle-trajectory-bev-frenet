## 1. 結論（論文の主張）

**一文で言うと**:
> bbox 下辺の基準点 f の最適な位置は、画像上の車線の傾きの向きで決まり、下辺中央（f=0.5）の代わりにそれに応じた f を使うと、大型車の横位置のずれを大きく減らせる。

| # | 結論 | 根拠の強さ |
|---|---|---|
| ① | **f\* の左右は、画像上の車線の傾きの向きで決まる**。右下がりなら右端寄り、右上がりなら左端寄り | 強い: I-24 の18カメラと scene_A の2本で、全車線が例外なし。P19 と scene_A では計算する前に予測して当たった |
| ② | **下辺中央（f=0.5）は、斜めの画角では最適ではない**。f\* を使うと、ずれが約 1.00 m から約 0.2 m に減る（I-24） | 強い: ポールを1本ずつ抜いて検証しても同じ |
| ③ | **真横の画角では f で直らない**。ずれは車幅の差の半分（約 0.35 m）で説明できる | 強い: 6カメラ17車線で +0.345 ± 0.025 m |
| ④ | 同じデータセットの中では、f\* の値もカメラ単位でほぼ一定で、傾きが急なほど中央に寄る。ただし値はデータセットによって違う | 中くらい: I-24 の中では順位相関 0.67〜0.78。scene_A は予測より中央寄り（0.03 → 0.21、0.95 → 0.73） |
| ⑤ | 真値（3Dラベル）がなくても、普通車を基準にして f を評価できる。そのための f によらない車線の割り当て（占有判定） | 手法としての貢献 |

### 書き方の注意
- **「画角（近づく／遠ざかる）で決まる」とは書かない**。scene_A で否定された（近づくのに左端寄り、遠ざかるのに右端寄り）。効いているのは画像上の車線の傾きの向き
- ①は全車線で例外がないので「傾きの向きで決まる」と言い切ってよい。④の「値」は「I-24 の中では」と範囲を限定する
- 「最適」は「大型車と普通車の平均の差を 0 にする」という意味だと明記する。1台ずつのばらつきは残る
- 検出器は機械学習なので「機械学習を使わない」とは書かない。「3Dラベルも追加の学習もいらない」と書く

### 3. 問題設定・提案手法

入力から f\* を出すまでの処理を、順番に1回たどる流れにする。後の項目は前の項目を使う。

```
3.1 前提と入力
3.2 座標変換（BEV・Frenet）
3.3 基準点 f と大型車のずれ
3.4 車両の分類と車線の割り当て
3.5 評価指標とグラフの読み方   ← どんな f が良いかの基準
3.6 f の決め方                ← 実際にどう f を選んで軌跡を作るか
```

#### 3.1 前提と入力
- 入力1: 高速道路の固定カメラの映像から得た、検出・追跡の結果（フレームごとの bbox、車両 ID、クラス）
- 入力2: 路面のホモグラフィ H（既知とする。H の作り方は対象外）
- 前提: 路面は平面、高速道路、車線は道路に沿っている
- 目的: 各車両の、路面上の横位置を正しく出すこと

#### 3.2 座標変換
- **BEV 変換**: 画素 (u, v) を H で路面座標 (X, Y) [m] に変換する。**H が正しく変換できるのは路面の上にある点だけ**（3.3 のずれの根になるので必ず書く）。解像度の換算や反転の補正は1行で済ませる
- **Frenet 変換**: 道路はカーブしているので、道路に沿った座標 (s, d) にする。中心線は、下辺中央を使った普通車の軌跡から、真ん中の車線で1本作る。全 f で同じ中心線を使う（クラス間差は同じ車線の普通車との差なので、中心線の位置は結果に影響しない）。d の符号の決め方も書く

#### 3.3 基準点 f と大型車のずれ
問題提起ではなく、「この研究で調べる変数 f の説明」として書く。2から「BEV で路面に移す → bbox のどこを路面の点とするか（f）を決めないといけない」と自然につなげる。
- f の定義: p(f) = (x₁ + f(x₂ − x₁), y₂)。f=0 が左端、0.5 が中央、1 が右端。0〜1 を 0.125 刻みの9点で調べる
- なぜ下辺か: bbox の中で接地点に一番近いから。よく使われるのは f=0.5
- ずれの仕組み（**図1**）:
  - 斜めの画角: 車両は車線に沿って斜めに写るので、下辺のうち車体の真下に当たる部分が左右に寄る。右下がりの車線なら右端寄り、右上がりなら左端寄り（**α の直感的な説明はここ。記号 α はまだ出さない**）
  - 真横: 下辺は手前の側面の線になり、車幅の差の半分だけカメラ側にずれる
  - 傾きが急（正面に近い）: 下辺は前面か後面の幅になり、中央寄り
- 前提: 普通車は小さいので、f を変えても横位置があまり変わらない → 基準に使える（**数字で裏付ける: metrics_all.md の B3**）
- 注意: この図は直感的な説明で、検証したモデルではない（「車体の一番低い角」を幾何から予測する方法は値が合わなかった）

#### 3.4 車両の分類と車線の割り当て（手法の中心。分量が一番多い）
1. 前処理: 20フレーム未満の追跡を除く。車両の代表値は d のフレーム平均
2. 車線中心の検出: 普通車の d の分布の山。中央分離帯と対向車線（画像上で逆向きに走る車線）を除く
3. 大型車の定義: COCO の truck にはピックアップが含まれるので、クラスでは決めない。同じ車線の普通車と比べた bbox の大きさの比（1.6倍以上）。ピックアップは大型車から外す
4. 普通車の車線: f=0.5 で一番近い車線（3.3 の前提があるので、これでよい）
5. **循環の問題**: 大型車の車線を f=0.5 で決めると隣の車線に入り、f\* がその f に引き寄せられる。具体例（トラック 3568）を数字で示す
6. 大型車の車線: f=0, 0.5, 1 で同じなら、その車線（unique）。違えば占有判定。決まらなければ判定不能として除く
7. 占有判定（**図2**）: 「同じ車線で、トラックの真横に普通車はいられない」。車体が確実にある区間、衝突の数え方、判定の条件。下辺が車体の前端か後端かは**画角の判定（近づく／遠ざかる／真横）**で決める。**画角の判定は α とは別物**なので書き分ける
8. 車線変更の除外: 全 f のうち、d の変化が一番小さいものを使う（これも循環を避けるため）
9. 全 f で同じ車両を使う（比べる条件をそろえるため）

#### 3.5 評価指標とグラフの読み方（＝どんな f が良いか）
- 良い f の条件: 大型車の横位置が、同じ車線の普通車と一致すること → Δ(f) = 0 となる f\*
- 指標: 車両の代表値 d̄ᵢ(f)、Δℓ(f)（符号は「＋ ＝ カメラ側」）、95%区間（Welch）、f\* と f\* の区間、「f依存なし」（\|Δ(1) − Δ(0)\| < 0.25 m）、カメラ単位の f\*（1/分散 で重み付け）、台数の下限、走行状態（60 km/h で分ける）
- **グラフの読み方**（模式図を1枚付ける）:
  - 横軸 f、縦軸 Δ、線が車線
  - 線が 0 を横切る（斜めの画角）: 横切る点が f\*
  - 線が水平（真横）: どの f でもずれが同じ。f では直せない
  - 線が 0 に届かない: 端が一番良いが、ずれは残る
  - 区間が広いときは f\* がはっきり決まっていない
- α はここには入れない（5は f の良し悪しを測る物差しで、α とは関係しない）

#### 3.6 f の決め方（＝実際にどう f を選んで軌跡を作るか）
- f を決める方法は2通り:
  - (a) そのカメラで大型車が十分に取れる → 3.5 の手順で、そのカメラの f\* を直接求める
  - (b) 新しいカメラで評価の余裕がない → **α から決める**
- **α の定義**: その車線の普通車（50 px 以上動いたもの）について、追跡の最初と最後の下辺中央の画像上の移動の向きを、画像の横軸から測った角度。＋ = 右下がり、− = 右上がり、0 = 水平。進む向き（近づく／遠ざかる）は区別しない。画像上の軌跡だけで測るので H もカメラ位置も使わず、普通車だけで測れる
- 規則: α の向きで左右を選ぶ（右下がり → 右端寄り、右上がり → 左端寄り、水平 → f では直らない）。**カメラ単位で1つの f を使う**（同じカメラの車線どうしでは差が見えないため）
- 軌跡の作り方: 決めた f を**すべての車両**の bbox に使い、路面座標と (s, d) を作り直す（普通車は f でほとんど動かないので、大型車だけ別の f にする必要はない）
- 真横の画角: f では直らない。車幅の差による補正は今後の課題
- **「α の向きで左右が決まる」は実験で分かったこと**なので、3.6 には手順だけを書き、成り立つかどうかは4章で示す
