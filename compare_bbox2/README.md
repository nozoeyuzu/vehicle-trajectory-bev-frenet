## 0. 研究の目的と現時点の結論

### 目的
高速道路の車両軌跡で、**大型車（トラック・バス）と普通車の横方向の位置にクラス間の差**が出る。
これを、**bbox 下辺のどこを基準点にするか**（f: 0 = 左端、0.5 = 中央、1 = 右端）を選ぶことでなくせないか、
また**画角ごとに最適な f（f\*）の傾向**があるかを調べる。

```
        bbox
   ┌──────────────┐
   │              │
   │    車 両      │
   │              │
   └──●─────●─────●┘  ← 下辺
     f=0   f=0.5  f=1
```

### 現時点の結論（暫定）

3本のポール（P33・P10・P19）の15分版、18カメラで確認した。f\* は大型車が5台以上判定できた車線の値。

| 画角 | カメラ | P33 | P10 | P19 | ひとこと |
|---|---|---|---|---|---|
| 近づいてくる（左上→右下） | C01, C02 | 0.72〜0.98 | 0.80〜0.98 | 0.80〜0.91（C01 L4 はほぼ 1.0） | **右端寄り（約 0.9）**。f=1 ちょうどだと行き過ぎる |
| 真横 | C03, C04 | f に依存しない、+0.28〜0.41 m | f に依存しない、+0.19〜0.43 m（C03 L4 の +0.81 を除く） | f に依存しない、+0.25〜0.42 m | 大型車は常に**カメラ側へ約 +0.3 m** ずれる。f では直せない（車幅差の半分 ≈ 0.35 m） |
| 遠ざかる（左下→右上） | C05, C06 | 0.04〜0.26（C05 L2 の 0.67 を除く） | 0.08〜0.16（C05 L2 の 0.55 を除く） | 0.00〜0.22 | **左端寄り（約 0.1〜0.2）**。C05 はトラクターの別検出で値が中央寄りに引っ張られる（[既知の限界](#既知の限界-トラクターの別検出による車線の取り違え)） |

- **画像上の車線の傾き α で f\* が決まる**: 右下がり（＋）なら右端寄り、右上がり（−）なら左端寄り、水平（0°）なら f に依存しない。さらに傾きが急なほど端から中央へ寄る（カメラ単位の12台で順位相関 0.67〜0.78。まとめ方で変わる。近づく画角でははっきり、遠ざかる画角では弱い）。ただし**同じカメラの車線どうしでは差が見えない**ので、規則は「カメラごとに1つの f\*」として扱う（[傾きの分析](#3ポールの傾きの分析)）
- **実用上の効果**: bbox 下辺の中央（f=0.5）の代わりに画角ごとの f（近づく ≈ 0.9、遠ざかる ≈ 0.1）を使うと、大型車と普通車のずれが **1.00 m → 0.22 m** に減る。2本のポールで決めた f を残りの1本に当てはめても同じ（[3ポール18カメラのまとめ](#3ポール18カメラのまとめ分析)）
- 真横のずれは6カメラ17車線で **+0.345 m（95%区間 ±0.025）**。車幅の差の半分（≈ 0.35 m）とほぼ一致する
- P19 では、f\* を計算する前に書いた予測のうち、左右の向き（14車線すべて）・真横（2台とも）・各車線の値（14車線中10車線が ±0.08 以内）が当たった（[7章](#テストデータの事前予測処理する前に書く)）

## 1. 見つかった問題と対処（今日の試行錯誤の記録）

時系列で並べています。**問題 1・2 が特に重要**で、元の `compare_bbox` の結果（「f=0.5 付近が最適」など）は、主にこの2つの影響を受けていました。

### 問題1: ホモグラフィに渡す画素座標が半分だった

| | 内容 |
|---|---|
| **何がダメだったか** | I-24 のホモグラフィ H は **4K（3840×2160）の画素座標**を前提に作られている。追跡データは **1080p（1920×1080）** の座標で、それをそのまま H に入れていた |
| **どうなっていたか** | すべての点が「4K 画像の別の場所」として変換されていた。単純な縮小ではなく、場所によって違う歪み方をする。<br>・車線間隔が 2.2〜2.9 m（C03 は 4.1〜5.0 m）になっていた。正しくは約 3.66 m<br>・クラス間差（m）も f\* も、歪んだ座標の上での値だった |
| **何を足したか** | 画素座標を **2倍してから** H に入れる（`common.py` の `SCALE = 3840 / 1920`） |
| **正しいことの根拠** | ・車線間隔が 3.5〜4.0 m になる<br>・6カメラの H から逆算したカメラ位置が、**すべて同じポールの ±3 m 以内、高さ 32〜34 m** に集まる<br>・真横から見た普通車の下辺の長さが約 4.9 m（車長に一致） |

```
同じ地点（画面の右下隅）
  4K の画素番号    : (3840, 2160)   ← H はこの番号を想定
  1080p の画素番号 : (1920, 1080)   ← 以前はこれをそのまま入れていた
                                       → H は「4K 画像の真ん中」だと解釈していた
```

**補足（WB / EB の H について）**: 「どちらの車道の H を使うか」は別の問題。
- H は路面ごとに作られている（WB 車道用、EB 車道用）。評価している車道と同じ側の H を使う
- C03 は向こう側の EB 車道を撮影しているので EB 用（WB 用の H は NaN で使えない）。C04 は手前の WB 車道なので WB 用（EB 用は NaN）
- ×2 は、WB / EB どちらの H でも必要

### 問題2: トラックが隣の車線に割り当てられていた（車線割り当ての循環）

**今日一番大きな問題です。**

| | 内容 |
|---|---|
| **何がダメだったか** | 車線を **f=0.5 で測った横位置**で決めていた。斜めの画角では、トラックの f=0.5 の点は**車体ではなく横の路面上**に落ち、約1車線分ずれる |
| **どうなっていたか** | トラックが**隣の車線**に割り当てられ、間違った車線の普通車と比べられていた。ずれは最大でも半車線（±1.85 m）にしかならないので、**大きなずれが小さく折り返される**。<br>→ クラス間差が実際より小さく見える<br>→ f\* が「車線を決めた f」に引き寄せられる（f=0 で決めると f\*≈0、f=1 で決めると f\*≈0.9 になった） |

**具体例（C02 のトラック 3568、目視では L3 = 元の N3 を走行）**

| | f=0 | f=0.5 | f=1 |
|---|---|---|---|
| トラックの d | 6.76 | 2.24 | −2.21 |
| 隣の車線（N2）の普通車の中心 | 5.55 | 3.93 | 2.33 |
| 本当の車線（N3）の普通車の中心 | 1.56 | −0.05 | −1.67 |

f=0.5 で見ると、トラック（2.24）は N3（−0.05）より N2（3.93）に近いので、N2 と判定される。
- 間違った車線（N2）基準のずれ: −1.69 m
- 本当の車線（N3）基準のずれ: +2.29 m

さらに、元の評価の「車線またぎ除外」（中心から 1 m 以上離れたら除外）で、こうしたトラックが落とされていた（問題3）。

**対処の検討**

| 方法 | 内容 | 判断 |
|---|---|---|
| A. 目視ラベル | 人が車線を記録する | 最も確実だが、時間がないので見送り |
| **B. 占有判定** | 「同じ車線の、トラックの真横に普通車はいられない」を使う | **採用**（詳細は [3.3](#33-ステップ3-assign_lane_occupancypy--大型車の定義と車線割り当て)） |
| C. セグメンテーション | bbox ではなく車両の輪郭を使う | 将来の比較対象の候補 |
| D. 3D の箱の推定 | 車両を地面に置いた箱として復元する | 試したが、真横以外では観測と合わなかった（下の「参考」） |

**検証**: 目視で確認した8台のうち、占有判定できた5台中4台が一致した。不一致の1台は、トラック2台が並走していて目視でも自信がない。
判定に迷う車両は、誤った車線を出すのではなく「判定不能」として評価から外すようにした。

### 問題4: 「大型車」に普通車サイズのピックアップが混ざっていた

| | 内容 |
|---|---|
| **何がダメだったか** | 大型車を COCO のクラス（5 = bus、7 = truck）で決めていた。COCO の truck には**ピックアップトラック**が含まれる |
| **どうなっていたか** | truck 424台中103台が普通車サイズだった。ピックアップのクラス間差はほぼ 0 なので、大型車の平均的なずれが薄まっていた。逆に、car 判定の中に大型車サイズのものが104台あった |

### 参考: カメラ幾何から作った「3D の箱モデル」（試したが採用せず）

H から逆算したカメラで、車両を地面に置いた箱として投影し、f\* を理論的に予測した。

- **真横**: 予測 +0.30〜0.54 m に対して観測 +0.27〜0.44 m で、定量的に合った（「大型車はカメラ側に車幅差の半分ずれる」の裏付け）
- **斜め**: 予測は端点（f≈1 または f≈0）。焦点距離を合わせ込んでも、普通車の bbox の大きさを 15〜30% 大きく予測し、合わなかった。遠ざかる画角では、トレーラーの後部の床が高く「地面に接した箱」ではないことも原因と考えられる

### 15分版（C06）で見つかった、占有判定の3つの不具合

15分版の C06 を処理したところ、**ずれが −2〜−3 m（ほぼ1車線分）の大型車**が何台か出た。調べると占有判定に問題があった。

| | 何がダメだったか | どうなっていたか | 何を足したか |
|---|---|---|---|
| **不具合1** | 車体を前後どちらに伸ばすかを、**トラック自身の動き**から決めていた | 止まっているトラックは向きがランダムに逆になり、車体の範囲を反対側に取っていた（15分版は車両の 83% が渋滞中）。例: 7211 / 7256 / 7306（停止中に ID が振り直された同じトラック） | 進行方向は**車道全体の普通車の多数決**で決める |
| **不具合2** | YOLO がトラックの一部（キャビンなど）を別の「普通車」として二重検出する | その「普通車」はトラックと一緒に動くので、ずっと衝突と数えていた。例: トラック 21963 の衝突相手は bbox の 96% がトラックの中 | トラックの bbox に**半分以上入っている検出は数えない**（`MAX_INSIDE = 0.5`） |
| **不具合3** | トラックの長さを 20 m（セミトレーラー）と仮定していた | 短いトラックで、15 m 前を走る隣の車線の車まで数えていた。例: トラック 1896（大きさ 1.94 倍） | **16 m** に変更。10〜20 m のどれでも f\* はほぼ同じことを確認 |

修正後: ずれが2 m 以上外れる大型車は **67台中1台**。C06 15分版の L3 のばらつきは 0.88 m → 0.60 m に下がった。

#### 既知の限界: トラクターの別検出による車線の取り違え（対策は入れていない）

| | 内容 |
|---|---|
| **何が起きているか** | YOLO が**トレーラー部分だけ**を truck として検出し、前の**トラクター（運転席）を別の「普通車」**として検出することがある。そのトラクターは、トラックの本当の車線の、すぐ前にいる「普通車」として扱われ、占有判定で「本当の車線に衝突あり」となり、**隣の車線と誤判定**される |

## 3. 各ステップの詳細

### 3.1 ステップ① `make_refpoint_csv_I24.py` — 地面座標を作る

1. 追跡 CSV と H を読む
2. 各 f（0, 0.125, …, 1）について、bbox 下辺上の点 `(x1 + f·(x2−x1), y2)` を求める
3. その点を **×2（4K に換算）→ H → State Plane [ft] → [m]** と変換する
4. 全 f の座標を `*_refpoints.csv` に、f=0.5 の座標を `X_meter, Y_meter` として `*_f0.500.csv` に保存する（中心線の作成用）

### 3.2 ステップ② `frenet_sweep.py` — 道路に沿った座標にする

1. `*_f0.500.csv` から、`frenet_transform.py` の auto で**中心線を1本**作る（普通車の軌跡の中央値から）
   - 中心線に使う車線: 普通車の横位置の分布の山から車線を**自動検出**し、**真ん中の車線**を使う（車線数が偶数なら、真ん中の2本のうち台数の多い方）。車線数を指定する必要はない
2. 全 f の点を、その中心線に対する **s（道なり距離）・d（中心線からの横距離）** に変換する
3. 中心線の端（1 m 以内）の点は外挿になるので `s_valid = False` にする

なぜ中心線を1本にするか: クラス間差は「同じ車線の普通車との差」で測るので、中心線を共通にしても評価は変わらない。
f ごとに作ると、基準にする車線が入れ替わることがある。

### 3.3 ステップ③ `assign_lane_occupancy.py` — 大型車の定義と車線割り当て

```
 ③-1 車両ごとの代表値         d の平均・標準偏差（f ごと）、大きさ、速度、
   │                          車線変更量（f=0〜1 の「前半→後半の d の変化」のうち最小のもの）
   │
 ③-2 車線中心の検出            普通車の d の分布の山 → 中央分離帯で車道を分け、評価する車道だけ残す
   │
 ③-3 カメラ位置と車線名        H からカメラ位置を逆算 → カメラに近い順に L1, L2, …
   │                          「カメラ側」の符号もここで決める
 ③-4 画角の判定                画像上の車の動く向き → 近づく(approach) / 遠ざかる(recede) / 真横(side)
   │
 ③-5 大型車の定義              同じ車線の普通車と比べた大きさ → car / pickup / large / other
   │
 ③-6 普通車の車線              普通車サイズは f によるずれが小さいので、f=0.5 の最寄り車線
   │
 ③-7 ★大型車の車線             f=0, 0.5, 1 での最寄り車線が全部同じ → その車線（unique）
                              違う → 占有判定（occupancy）/ 判定不能（undecided）
```

#### 占有判定の考え方

「**同じ車線の、トラックの真横に普通車はいられない**」

```
進行方向 →→→

L2: ─────────── 🚗 ──────────────   ← 普通車（車線判定は確実）
L3: ──────[■■■■ トラック ■■■■]───
              ↑ここに普通車がいる

→ トラックが L2 にいるなら、この普通車と重なってしまう
→ だからトラックは L2 ではなく L3
```

#### 占有判定の手順（各フレームで）

**手順1: トラックの「端」の位置を出す**

bbox の下辺は、トラックの中心ではなく**端**に当たる。どちらの端かは画角で決まる。

```
近づく画角（C01, C02）            遠ざかる画角（C05, C06）          真横（C03, C04）
  下辺 = 前端（前バンパー）          下辺 = 後端（トレーラー後部）      下辺 = 車体全長に掛かる
```

下辺のどこが端なのかは正確には分からないので、「f=0〜1 の点の s の範囲 [lo, hi] のどこか」とする。

**手順2: 「確実に車体がある区間」を決める**

```
近づく画角（端 = 前端、車体は後ろへ伸びる）

  s →  （進行方向）
        |←────────── 長さ L = 16 m ──────────→|
        ................[ 確実に車体がある区間 ]..[lo  hi]
                                             前端はこの間のどこか
  区間 = (hi − L + 余裕,  lo − 余裕)      余裕 = 2 m

遠ざかる画角（端 = 後端、車体は前へ伸びる）
  区間 = (hi + 余裕,  lo + L − 余裕)

真横
  区間 = (lo + 余裕,  hi − 余裕)
```

進行方向は、車道全体の普通車の多数決で決める（トラック自身の動きは使わない ← 不具合1の修正）。

**手順3: 候補車線ごとに衝突を数える**

- 候補車線 = f=0, 0.5, 1 で割り当てられうる車線と、その間の車線
- 基準車 = 普通車サイズ（size < 1.4）で、車線中心から 1 m 以内、車線変更していない車両
- その区間の真横に基準車がいるフレームを「衝突」とする
- ただし、基準車の bbox がトラックの bbox に半分以上入っているフレームは数えない（二重検出 ← 不具合2の修正）

**手順4: 判定する**

| 条件 | 結果 |
|---|---|
| 1つの車線だけ衝突 ≤ 1 フレーム、かつ他の候補車線は衝突 ≥ 5 フレーム（≥ 1台） | その車線（`occupancy`） |
| それ以外 | 判定不能（`undecided`）→ 評価から外す |

`vehicles.csv` の `conflicts` 列に、候補車線ごとの衝突が `{'L3': '0f/0台', 'L2': '50f/2台'}`（フレーム数／台数）の形で残る。

注意: トラクターが別の「普通車」として検出されると、この判定が誤ることがある（[既知の限界](#既知の限界-トラクターの別検出による車線の取り違え)）。

### 3.4 ステップ④ `evaluate_refpoint.py` — クラス間差と f\*

| 項目 | 定義 |
|---|---|
| 代表値 | 車両ごとの d の平均（f ごと） |
| クラス間差 | 大型車の代表値の平均 − 同じ車線の普通車の代表値の平均。**＋ = 大型車がカメラ側にずれている** |
| 95%区間 | Welch の t 近似（1.96 × 標準誤差） |
| f\* | クラス間差が 0 になる f（f の間は線形補間） |
| f\* の区間 | クラス間差の 95%区間が 0 を含む f の範囲 |
| f依存なし | f=0→1 でクラス間差が 0.25 m 未満しか変わらない（真横の画角） |
| 対象車両 | 普通車: 車線中心から半車線以内。大型車: `unique` か `occupancy` で車線が決まったもの。どちらも車線変更車は除く。**全 f で同じ車両集合** |
| 走行状態 | `all` / `free`（60 km/h 以上）/ `congested`（60 km/h 未満）。同じ状態の車両どうしで比べる |
| 参考 | ピックアップ（truck のうち普通車サイズ）の普通車との差も出す（**CSV のみ**。グラフ `refpoint_sweep.png` は大型車 − 普通車だけ） |

### 3ポールの傾きの分析

`analyze_fstar_angle.py` で、画像上の車線の傾き α（その車線の普通車の接地点の移動方向。画像の横軸から測り、＋ = 右下がり、− = 右上がり）と f\* の関係を調べた。画像上の軌跡だけから測るので、外れることがあるカメラ位置は使わない。出力は `out_fstar_angle/`（`fstar_angle.csv`、`fstar_angle.png`）。

```bash
python compare_bbox2/analyze_fstar_angle.py $(for p in P33 P10 P19; do for c in 1 2 3 4 5 6; do echo -n "${p}C0${c}_15min "; done; done)
```

| 傾き α | 画角 | f\* |
|---|---|---|
| +41〜+61° | 近づく | 右端寄り（0.62〜0.98） |
| 約 0°（−0.9〜+1.1°） | 真横 | f に依存しない（f=0→1 でクラス間差の変化が 0.2 m 以下） |
| −43〜−65° | 遠ざかる | 左端寄り（0.00〜0.26。トラクターの別検出の影響を受けた C05 L2 を除く） |

- **傾きの向きで、f\* の左右が決まる**。3ポールの全車線で例外なし
- **傾きが急なほど、f\* が端から中央へ寄る**。「端からの距離」（近づく画角は 1 − f\*、遠ざかる画角は f\*）と |α| の順位相関は、95%区間の幅が 0.4 未満の31車線で 0.67（p < 0.001）、カメラ単位（12台、大型車の台数で重み付けした平均）で **0.78（p = 0.003）**。直線を当てはめると、端からの距離 = 0.0067 × |α| − 0.221（P33・P10 だけでは 0.0093 × |α| − 0.342、P19 だけでは 0.0058 × |α| − 0.180）
- **同じカメラの車線どうしでは、傾きによる差は見えない**。1台のカメラの中の傾きの差（10〜12°）では、f\* の差が区間の幅に埋もれる。P19 の事前予測でも、車線ごとの差の予測は外れた。規則は「カメラごとに1つの f\*」として扱う
- **注意**: 傾きのデータは約 0° と ±41〜65° にしかなく、10〜40° や 65° 以上は確かめていない。「真横（0°）では f に依存しない」と「斜め（±41〜65°）では端から 0〜0.25」の間をどうつながるかは、そうした画角のデータで確かめる必要がある。また、カメラに近い車線ほど傾きが急なので、傾きの効果とカメラからの距離の効果は区別できていない

| R1: 画角ごとの f（学習用カメラの f\* の平均。近づく ≈ 0.9、遠ざかる ≈ 0.1） | **0.22 m** | 0.19 m | 78% |
| R2: 傾きから決める f（端からの距離 = a·\|α\| + b を学習用カメラで当てはめる） | **0.19 m** | 0.12 m | 78% |

|---|---|---|---|---|
| P33 | 1.01 m | 0.31 m | 0.34 m | 0.27 m |

- **中央（f=0.5）をやめて画角ごとの f にするだけで、ずれが約5分の1になる**。どのポールを抜いても同じ
- 傾きの規則（R2）は、画角ごとの規則（R1）より少し良い程度（平均 0.22 → 0.19 m）。実用上は「近づくなら 0.9、遠ざかるなら 0.1」でほぼ十分
- そのカメラ自身の f\* を使っても 0.17 m までしか下がらないので、規則の性能は上限に近い。残る 0.17 m は、車線間のばらつきと既知の限界（トラクターの別検出）による
- P33 を抜いたときに残るずれが大きい（0.31 m）のは、P33 C05 L2（トラクターの別検出の影響）を含むため

**3. 真横: 車幅の差の半分で説明できる**
- 6カメラ17車線をまとめると、大型車のカメラ側へのずれ（f=0.5）は **+0.345 m（95%区間 ±0.025、1/分散で重み付け）**。f=0→1 の変化は最大 0.19 m で、f には依存しない
- 大型車と普通車の車幅の差の半分（(2.6 − 1.9) / 2 ≈ 0.35 m）とほぼ一致する。f では直せないが、クラスごとの幅による補正（大型車をカメラから約 0.35 m 遠ざける）で直せる見込みがある
- 3ポールすべてで、C04（手前の WB 車道、カメラから 10〜18 m）の方が C03（向こう側の EB 車道、28〜43 m）よりずれが大きい（+0.35〜0.39 m と +0.27〜0.33 m）。ただし C03 は自由走行、C04 は渋滞中なので、カメラからの距離の効果か交通状況の効果かは区別できない

**4. 傾きの規則の強さ（カメラ単位）**
- 12台で、|α| と端からの距離の順位相関は **0.67（p = 0.017）**、相関係数 0.76（p = 0.004）。端からの距離 = 0.0074 × |α| − 0.275。[3ポールの傾きの分析](#3ポールの傾きの分析)の 0.78 は、車線を大型車の台数で重み付けした別のまとめ方での値で、まとめ方で値が変わる
- **近づく画角だけでは 0.94、遠ざかる画角だけでは 0.31**。遠ざかる画角は C05 がトラクターの別検出で乱れており、特に P19 C05（0.02）が外れる（除くと全体で 0.77）

**論文に向けたまとめ（暫定）**
1. bbox 下辺の中央ではなく、画角に応じた f（近づく ≈ 0.9、遠ざかる ≈ 0.1）を使うと、大型車のずれが約 1 m から約 0.2 m に減る。3ポール18カメラで、別のポールにもそのまま使えることを確かめた
2. 真横の画角では f で直らないが、ずれは車幅の差の半分（≈ 0.35 m）で説明できる
3. 限界: 傾きのデータが約 0° と ±41〜65° しかない。遠ざかる画角はトラクターの別検出の影響を受ける。真値（車両の本当の中心）とは比べておらず、評価は「大型車と普通車の差が 0 になる f」という間接的な指標

## 6. 研究としてのパラメータの扱い方

パラメータを4種類に分けて考える。

| 種類 | 例 | 扱い |
|---|---|---|
| ① 入力（場面の事実） | fps、解像度、H の解像度、車線幅 | **問題なし**。キャリブレーションと同じ入力データ。メタ情報から自動で読むのが理想。論文では「入力」と明記 |
| ② データから推定すべき量 | 車線数、中央分離帯の位置 | **固定で書くのは欠陥**。データから自動推定するよう直す |
| ③ アルゴリズムの設定値 | 衝突しきい値、トラックの長さ、大きさのしきい値 | **全カメラで同じ値に固定**し、根拠と感度を示す。**カメラごとに変えない** |
| ④ 適用範囲の前提 | 高速道路、米国の車両構成、渋滞の定義 | 論文の「適用範囲・限界」に明記 |

**一番大事なこと**: 結果を見ながらカメラごとに設定値を調整しない（後付けの調整 = 過学習）。研究では次の3つを示す。
1. 値の決め方の根拠（物理的な理由、または開発用データで決めた）
2. 感度分析（値を変えても結論が変わらない）
3. 使っていないデータでの検証（コードと設定値を変えずに）

**今の状況**: 修正も設定値の選択も、C06 15分版を含む全カメラのデータを見ながら行ったので、**今の結果は開発段階**。

2. 各車線の f\* が、上の表の予測の範囲に入る
3. 同じカメラの中で、カメラから遠い（傾きが緩い）車線ほど f\* が端に近い（C01: L1 < L2 < L3 < L4、C02: L1 < L2 < L3、C05: L1 > L2 > L3、C06: L1 > L2 > L3 > L4）
4. 傾きが急なカメラほど f\* が中央に寄る（C02 は C01 より小さい、C06 は C05 より大きい）
5. 真横は上の2点

- C02 L1（61.3°）と C06 L1・L2（64.5°、59.5°）は、予測式を作った範囲（41〜59°）の外。特に C06 L1 は、傾きの範囲を広げて規則を試すことになる
- 予測 3 と 4 は、P33・P10 では弱い傾向だった（順位相関 0.62）ものを試す

結果（2026-10-09、予測をコミット（`5329dee`）した後に f\* を計算。評価方法は変えていない）:
- 表の ○ = 予測の範囲内、△ = わずかに外（0.02 以内）か台数が少ない、✗ = はっきり外れ（95%区間も予測と重ならない）
- **予測 1（左右の向き）: 全14車線で当たった**
- **予測 2（予測の範囲）: 14車線中 10車線が範囲内**。はっきり外れたのは C01 L1 だけ（予測 0.79、結果 0.90）。△ の3車線は、0.01〜0.02 だけ外か、f\* がほぼ 1.0（C01 L4、8台）
- **予測 3（同じカメラの中で、遠い車線ほど端に近い）: 外れ**。成り立ったのは C06（0.22 > 0.18 > 0.14 > 0.06）だけ。C01（0.90, 0.90, 0.86）・C02（0.82, 0.84, 0.80）・C05 は順番が合わない。カメラの中での傾きの差（C01 で 12°）では、f\* の差は区間の幅に埋もれる
- **予測 4（傾きが急なカメラほど中央寄り）: ほぼ当たった**。C02 は3車線とも C01 より小さい（中央寄り）。C06 は L1・L3 で C05 より大きい（L2 は逆）
- **予測 5（真横）: 当たった**。C03 は f=0→1 の変化 −0.06〜−0.12 m（f依存なし）、大型車のずれ +0.25〜+0.29 m。C04 は変化 +0.01〜+0.02 m、ずれ +0.33・+0.42 m
- **傾きの範囲を広げた C06 L1（64.5°）も 0.22 で予測の範囲内**。傾きが急なほど端から内側に寄る関係は、59° より先でも続いた
- 3ポール合わせた傾きの分析（`analyze_fstar_angle.py`、95%区間の幅 < 0.4 の31車線）: 端からの距離と |α| の順位相関 0.67（p < 0.001）。カメラ単位（12台、大型車の台数で重み付けした平均）では 0.78（p = 0.003）。**関係はカメラ単位でははっきりしているが、同じカメラの車線どうしでは見えない**
- 予測式の傾きは、P33・P10 だけ（0.0093）より P19 だけ（0.0058）の方が緩い。3ポール合わせると 0.0067 × |α| − 0.221

C01 L1 の外れの調査（2026-10-09）:
- **車線の判定は正しい**: L1 の大型車64台中63台が unique。L1 はカメラ側の端の車線で外側に車線がないので、unique になるのは自然。画像でも路肩側の車線を走っていた。f\* = 0.90 で見て普通車から 1.5 m 以上外れる大型車は1台、ばらつき 0.55 m
- **走行状態・車両の大きさでは説明できない**: 渋滞中だけで 0.92。C01 では大きい車両（普通車の 2.7 倍以上）ほど端寄りだが、他のカメラでは22車線中12車線でしか成り立たず、大きい車両の割合（58%）も他のカメラの L1 と同程度
- **理由は、C01 の中で f\* が車線によらずほぼ一定（L1 0.90、L2 0.90、L3 0.86）だったこと**。予測は車線ごとの傾き（59.5° → 50.2°）に合わせて 0.79 → 0.87 と変えていたので、傾きが一番急な L1 が一番外れた。予測 3 の外れの一番目立つ例で、L1 自体の問題ではない。カメラ単位（大型車の台数で重み付けした傾き 55.5°）で予測すれば 0.83 で、結果（約 0.89）は範囲内
- **結論: 傾きと f\* の規則は、カメラ単位では成り立つが、車線単位では成り立たない**。P33 C01 で見えた車線ごとの変化（0.75 → 0.98）は P19 C01 で再現しなかったので、車線間の差はばらつき（トラックの構成など）の範囲と考える。規則は「カメラごとに1つの f\*」として扱う

### 用語

| 用語 | 意味 |
|---|---|
| f | bbox 下辺上の基準点の位置（0 = 左端、0.5 = 中央、1 = 右端） |
| f\* | 大型車と普通車のクラス間差が 0 になる f |
| s / d | 中心線に沿った道なり距離 / 中心線からの横距離（進行方向に向かって左が正） |
| クラス間差 | 大型車の横位置の平均 − 同じ車線の普通車の平均。このドキュメントでは「＋ = カメラ側」 |
| 占有判定 | 「同じ車線の、トラックの真横に普通車はいられない」を使った、f に依存しない車線判定 |
| 基準車 | 占有判定の手がかりにする、車線が確実な普通車サイズの車両 |
| unique / occupancy / undecided / lane_change | 大型車の車線の決まり方: f によらず同じ車線 / 占有判定で決定 / 判定不能 / 車線変更で除外 |
| WB / EB | 西行き / 東行きの車道。H は車道ごとにある |
| approach / recede / side | 近づく画角 / 遠ざかる画角 / 真横 |
